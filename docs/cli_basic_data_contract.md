# `preprocess basic` (`cli_basic`) data contract

This document defines the data contracts for the BaSiC illumination template CLI
implemented in `fishtools/preprocess/cli_basic.py`. It covers the public Click
group and subcommands:

- `preprocess basic run`
- `preprocess basic batch`

The goal is to make the expected filesystem layout, inputs, and produced
artifacts explicit, and to show how these BaSiC profiles are consumed by
`preprocess deconvnew` (see `docs/cli_deconv_data_contract.md`).

---

## Position in the end‑to‑end pipeline

`preprocess basic` is an **early preprocessing stage** used to estimate
illumination fields (BaSiC darkfield/flatfield) for each imaging channel.

Typical order of operations:

1. Raw data are written by acquisition under:

   ```text
   <workspace>/{round}--{roi}/{round}-{idx:04d}.tif
   ```

2. `preprocess basic run` / `batch`:

   - Samples a subset of **interior** tiles per round/ROI using ROI layout CSVs.
   - Extracts representative z‑slices per channel.
   - Fits a `BaSiC` model per channel.
   - Writes BaSiC profiles and diagnostic plots under:

     ```text
     <workspace>/basic/{label}-{channel}.pkl
     <workspace>/basic/{label}-{channel}.png
     <workspace>/basic/{label}-sampling.json
     ```

3. `preprocess deconvnew` (`cli_deconv`) consumes these profiles via
   `resolve_basic_paths` (see `fishtools/preprocess/deconv/basic_utils.py`):

   - For a round `{round}` and channels `["560", "650", "750"]`, it prefers:

     ```text
     <workspace>/basic/{round}-{channel}.pkl
     ```

     falling back to:

     ```text
     <workspace>/basic/all-{channel}.pkl
     ```

   - These are used to correct illumination during deconvolution and quantization
     (see `docs/cli_deconv_data_contract.md`, “BaSiC profiles and illumination
     correction”).

4. Downstream registration (`preprocess register`), stitching
   (`preprocess stitch`), and spot decoding (`preprocess spots`) operate on
   deconvolved tiles that have already had BaSiC correction applied by
   `preprocess deconvnew`.

## Workspace and path conventions

### Imaging root

`cli_basic` is designed to operate on a directory that contains round/ROI
subdirectories of the form:

```text
<root>/
  {round}--{roi}/
    {round}-0000.tif
    {round}-0001.tif
    ...
```

In a full fishtools workspace this root is normally the **workspace root**:

```text
<workspace>/{round}--{roi}/{round}-{idx:04d}.tif
<workspace>/analysis/...
```

The CLI arguments:

- `PATH` should point to this imaging root (usually `<workspace>`).
- BaSiC outputs are written to:

  ```text
  <PATH>/basic/
  ```

When using these profiles with `preprocess deconvnew`, you should pass the same
`PATH` as the `WORKSPACE` argument to `preprocess deconvnew ...`, so that
`resolve_basic_paths(PATH, ...)` can find `<PATH>/basic/*.pkl`.

### ROI layout CSVs (required)

BaSiC sampling relies on **ROI layout CSVs** that describe tile positions for
each ROI:

```text
<PATH>/{roi_base}.csv
```

Contract:

- One CSV per ROI base name (`roi_base`) as derived from the directory
  `<round}--{roi_base}` (ignores any `+codebook` suffix).
- CSV contains at least two columns (no header); the first two columns are
  interpreted as `x,y` tile coordinates.
- Row order defines the tile index: index `i` corresponds to the tile:

  ```text
  {round}--{roi_base}/{round}-{i:04d}.tif
  ```

During sampling, tiles are restricted to those at least 2 steps away from the
edges of the ROI grid using `tiles_at_least_n_steps_from_edges(..., n=2)`. If
no interior tiles can be found for any ROI (e.g. because all ROI CSVs are
missing), `run_with_extractor` raises:

> No interior tiles found for BaSiC sampling. ROI layout CSV files (e.g. '<roi>.csv') appear to be missing for all ROIs. Please generate ROI CSVs (e.g. via stitching helpers) before running 'preprocess basic run'.

In practice these ROI CSVs are typically generated by stitching helpers (see
`docs/cli_stitch_data_contract.md`).

## BaSiC profile outputs

### Per‑channel BaSiC pickle files

For each fitted channel, `fit_and_save_basic` writes a pickle payload:

```text
<PATH>/basic/{label}-{channel}.pkl
```

where:

- `{label}`:
  - equals the `round_` argument for `run`, or
  - `"all"` when `round_` is omitted/`None` (the “all‑rounds” mode).
- `{channel}`: channel label as returned by `get_channels(...)`, e.g.
  `"560"`, `"650"`, `"750"` or experiment‑specific names (`"chA"`, `"chB"`).

Payload contract:

- A pickled object that is either:
  - A dict containing a `"basic"` key, or
  - A BaSiC‑like object directly.
- When dict‑wrapped, the structure is:

  ```python
  {
      "basic": <BaSiC model>,
      "path": "<absolute_path_to_basic_dir>",
      "name": "<label>",
      "created_at": "YYYY-MM-DD HH:MM:SS",
  }
  ```

- The contained BaSiC object must expose:

  - `.darkfield` – 2D array `(H, W)` (float‑like, same shape for all channels).
  - `.flatfield` – 2D array `(H, W)` (float‑like, same shape).

`preprocess deconvnew` loads these files via `load_basic_profiles`, which
expects all profiles passed for a given round to share the same `(H, W)`
geometry. Any mismatch raises a `ValueError`.

### Diagnostic PNGs

For each BaSiC model, a diagnostic figure is written to:

```text
<PATH>/basic/{label}-{channel}.png
```

The plot encodes:

- Flatfield image.
- Darkfield image.
- Baseline vector over frames.

These PNGs are for visual QC only and are not consumed by other CLIs.

### Sampling manifest JSON

For each `run_with_extractor` invocation, a sampling manifest is written to:

```text
<PATH>/basic/{label}-sampling.json
```

where `{label}` is `round_` or `"all"` as above.

Fields:

- `round`: the label (`round_` or `"all"`).
- `seed`: random seed used for sampling (or `null`).
- `timestamp`: creation time (`YYYY-MM-DD HH:MM:SS`).
- `channels`: list of channel labels as returned by `get_channels`.
- `n_candidates`: total number of tiles considered after basic filtering.
- `n_selected`: number of tiles actually sampled.
- `sampled_tiles`: list of sampled tile paths:
  - Relative to `<PATH>` when possible.
  - Absolute paths otherwise.

Additional fields:

- When running in “all‑rounds” mode (`round_ is None`):
  - `extra_rounds`: list of non‑canonical rounds (see below).
  - `counts_by_round`: mapping `round_name -> n_selected_for_round`.
- When running for a single round:
  - `counts_by_roi`: mapping `roi_name -> n_selected_for_roi`.

These manifests are intended for reproducibility and auditing and are not
directly consumed by other CLIs.

## Sampling strategy and tile selection

### Canonical rounds and "all" mode

When `round_` is omitted (`None`), `run_with_extractor` enters an “all‑rounds”
mode where it:

1. Uses `Workspace.discover_rounds(PATH)` to collect all rounds.
2. For each round, picks a representative tile and calls `get_channels` to
   determine channel labels.
3. Marks a round as **canonical** when:

   - `get_channels(sample_tile)` returns exactly 3 channels, and
   - all channel labels are purely numeric (e.g. `"560"`, `"650"`, `"750"`).

4. Samples interior tiles only from canonical rounds, ensuring:

   - At most one tile per `(roi, index)` pair across canonical rounds
     (round‑robin assignment).
   - Non‑canonical rounds are collected in `extra_rounds` and processed later
     one‑by‑one.

The combined canonical sample is then passed to the extractor, and a single
BaSiC profile set labeled `"all"` is fitted:

```text
<PATH>/basic/all-560.pkl
<PATH>/basic/all-650.pkl
<PATH>/basic/all-750.pkl
```

After this global fit, `run_with_extractor` recursively runs per‑round fits for
any `extra_rounds`, producing per‑round profiles for atypical rounds.

`preprocess deconvnew` prefers round‑specific profiles when available and falls
back to these `all-*` profiles when they are missing.

### Per‑round mode

When `round_` is provided and is not `"all"`:

1. Candidate tiles are discovered via:

   ```text
   <PATH>/{round_}--*/*.tif
   ```

2. Files are sorted, with any `--basic` acquisition folders placed last (to
   avoid biasing sampling).
3. Channels are determined with `get_channels(files[0])`. If fewer than 100
   tiles are found, a `ValueError("Not enough files")` is raised. Between 100
   and 500 tiles, a warning is logged about reliability.
4. Tile selection is restricted to interior tiles defined by ROI CSVs
   (`tiles_at_least_n_steps_from_edges(..., n=2)`).
5. Up to 1000 interior tiles are sampled uniformly at random (controlled by
   `--seed`).
6. These sampled tiles are passed to the extractor to build the training stack.

The resulting profiles are stored under:

```text
<PATH>/basic/{round_}-{channel}.pkl
```

### "registered" special case

When `round_ == "registered"`, `run` switches to the alternate extractor
`extract_data_from_registered` and expects candidate tiles under:

```text
<PATH>/registered--{roi}+{codebook}/reg-{idx:04d}.tif
```

This mode:

- Treats each registered stack as `(Z, C, Y, X)`.
- Applies a max‑projection over `Z` to obtain `(C, Y, X)` per tile.
- Builds a training stack of shape `(n_tiles, C, Y, X)`.

This is primarily intended for experimentation/QC; the standard pipeline uses
BaSiC profiles trained on **raw** tiles prior to deconvolution.

## Data extractors

Two extractor implementations are provided and selected automatically by
`run`:

### `extract_data_from_tiff`

Used when `round_ != "registered"`.

Input contract:

- `files`: list of raw TIFF paths matching:

  ```text
  <PATH>/{round}--{roi}/{round}-{idx:04d}.tif
  ```

- TIFF structure:
  - All tiles have the same number of channels `nc` and z‑slices `nz` per
    channel.
  - Stored as a stack of pages in channel‑major order:
    `(z0_c0, z0_c1, ..., z0_c{nc-1}, z1_c0, ...)`.
  - Spatial shape is fixed at `2048 × 2048` pixels.

Parameters:

- `zs`: collection of relative z‑positions in `[0, 1]` (e.g. `(0.5,)`).
- `nc`: number of channels (must be provided; derived in `run_with_extractor`
  from `get_channels(files[0])`).
- `max_files`: maximum number of tiles to load (defaults to 500–1000, depending
  on mode).
- `deconv_meta`: optional deconvolution scaling metadata; when provided,
  `scale_deconv` is applied per channel. This is primarily for debugging and
  is not part of the standard pipeline.

Output:

- A NumPy array of shape:

  ```text
  (n_samples, nc, 2048, 2048), dtype=float32
  ```

  where `n_samples = min(len(files), max_files) * len(zs)`. Each sample
  corresponds to one `(file, z)` pair.

If any selected slice is entirely zeros, an exception is raised with file/z
context.

### `extract_data_from_registered`

Used when `round_ == "registered"`.

Input contract:

- `files`: list of registered TIFF stacks (paths under
  `<PATH>/registered--{roi}+{codebook}/`).

Behavior:

- Reads the first file to determine `(Z, C, H, W)` and infers `C`.
- For each file, computes `tif.asarray().max(axis=0)` to obtain `(C, H, W)`.
- Stacks results into:

  ```text
  (n_files, C, H, W), dtype=float32
  ```

The `zs` and `deconv_meta` parameters are ignored in this extractor.

## Command: `preprocess basic run`

### CLI signature

```text
preprocess basic run PATH ROUND [--zs ZS] [--overwrite] [--seed SEED]
```

Arguments:

- `PATH` (required):
  - Imaging root containing `{round}--{roi}` directories.
  - Typically the fishtools workspace root.
- `ROUND` (required):
  - Round token (e.g. `1_9_17`) for per‑round mode.
  - `"all"` to sample canonical rounds jointly and write `all-*.pkl`.
  - `"registered"` to train from registered stacks under
    `PATH/registered--{roi}+{codebook}/`.

Options:

- `--zs ZS` (default: `"0.5"`):
  - Comma‑separated list of relative z positions (e.g. `"0.25,0.5,0.75"`).
  - Each value must be in `[0, 1]`; otherwise a `ValueError` is raised.
- `--overwrite`:
  - If **absent** and files matching `<PATH>/basic/{ROUND}*` already exist,
    the command logs a message and returns without recomputing.
  - If **present**, existing profiles/plots are overwritten.
- `--seed SEED`:
  - Integer random seed used to make sampling reproducible.

### Inputs

- Raw or registered tiles, depending on `ROUND`:
  - Per‑round mode: `<PATH>/{ROUND}--{roi}/{ROUND}-{idx:04d}.tif`
  - All‑rounds mode: tiles from all canonical rounds discovered under `PATH`.
  - Registered mode: `<PATH>/registered--{roi}+{codebook}/reg-{idx:04d}.tif`
- ROI layout CSVs:

  ```text
  <PATH>/{roi}.csv
  ```

  must exist and be consistent with tile indices, or the command will fail with
  an informative error as described above.

### Outputs

For each channel label in `get_channels(files[0])`:

- BaSiC profile:

  ```text
  <PATH>/basic/{label}-{channel}.pkl
  ```

- Diagnostic PNG:

  ```text
  <PATH>/basic/{label}-{channel}.png
  ```

In addition:

- Sampling manifest:

  ```text
  <PATH>/basic/{label}-sampling.json
  ```

where `{label}` is:

- The `ROUND` argument in per‑round and registered modes.
- `"all"` in all‑rounds mode.

Logs are written under `<workspace>/analysis/logs` when `PATH` resolves inside a
fishtools workspace, via `setup_cli_logging`.

## Command: `preprocess basic batch`

### CLI signature

```text
preprocess basic batch PATH [--overwrite] [--threads N] [--zs ZS] [--seed SEED]
```

Arguments:

- `PATH` (required): imaging root (typically the workspace root).

Options:

- `--overwrite`:
  - Forwarded to `run`; when set, existing per‑round profiles are recomputed.
- `--threads, -t N` (default: `1`):
  - Maximum number of worker threads used to process rounds in parallel.
- `--zs ZS`:
  - Forwarded to each `run` invocation.
- `--seed SEED`:
  - Forwarded to each `run` invocation to make sampling deterministic across
    rounds.

### Behavior

- Discovers all rounds present under `PATH` by scanning directory names that
  match `{round}--{roi}`.
- For each round, submits a `run` call via a `ThreadPoolExecutor`:

  ```python
  run.callback(PATH, round_name, overwrite=overwrite, zs=zs, seed=seed)
  ```

- Waits for all futures to complete, propagating any exceptions.

### Inputs and outputs

`batch` is a thin orchestrator over `run` and therefore shares the same input
and output contracts:

- Inputs: raw per‑round tiles and ROI CSVs under `PATH`.
- Outputs: BaSiC profiles, diagnostic PNGs, and sampling manifests under
  `<PATH>/basic/` for each discovered round (and optionally `all-*.pkl` if you
  also run `preprocess basic run PATH all`).

## Relationship to deconvolution, registration, and stitching

`cli_basic` provides illumination correction profiles that are consumed by
downstream stages:

- **Deconvolution (`preprocess deconvnew`)**
  - Resolves BaSiC profiles via `resolve_basic_paths(PATH, round_name, channels, basic_name=None)`:

    - Prefers `<PATH>/basic/{round_name}-{channel}.pkl`.
    - Falls back to `<PATH>/basic/all-{channel}.pkl` when a round‑specific file
      is missing.

  - These profiles are loaded into GPU memory by `load_basic_profiles` and
    applied during deconvolution to correct darkfield and flatfield across all
    tiles (see `docs/cli_deconv_data_contract.md`).

- **Registration and stitching**
  - `preprocess register` and `preprocess stitch` do not read the BaSiC pickle
    files directly; instead they operate on deconvolved tiles that have already
    been corrected by `preprocess deconvnew`.
  - The ROI layout CSVs required by `cli_basic` are typically produced by
    stitching helpers (e.g. commands in `cli_stitch` that derive tile grids
    from ImageJ `TileConfiguration` files; see
    `docs/cli_stitch_data_contract.md`).

By keeping BaSiC profiles in `<workspace>/basic` and using a consistent
round/channel naming scheme, `cli_basic` ensures illumination correction is
reusable and unambiguous across deconvolution rounds and downstream CLIs.
